# GenSprite Phase 1 Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans to implement this plan task-by-task. Track progress with checkboxes below.

**Goal:** A working local stdio MCP server that produces a deterministic heart PNG and universal manifest, with honest technical and art-review status.

**Architecture:** Pydantic models define profiles, sprite requests, manifests, and reports. A filesystem asset store owns creation and validation; the official MCP Python SDK exposes five thin tools. Draw a deliberate heart mask at native resolution with Pillow, with no generated illustration or interpolation.

**Tech Stack:** Python 3.11+, official MCP SDK FastMCP (1.x), Pillow, Pydantic, pytest, Ruff; uv for a reproducible local environment.

**Spec:** `GenSprite_MCP_Project_Plan.md`, Phase 1 and pixel-art acceptance policy.

## Global Constraints

- Exact canvas dimensions, RGBA PNG, binary alpha, palette lock, portable relative paths.
- No `game_ready` claim without human art approval; Phase 1 always leaves art review pending.
- Never overwrite an asset or read/write outside the configured store; use generated IDs.
- Preserve the supplied plan's requirements; apply the user's GenSprite rename and implement Phase 1 before later phases.
- Use standard library operations rather than a database or additional processing dependencies.

## Review Focus

- Invalid, enormous, boolean, or fractional dimensions must fail before allocating images.
- Palette formats, empty/duplicate palettes, and disallowed pixel colors must be handled explicitly.
- Traversal, absolute paths, symlinks, and corrupt manifests must not escape the asset store.
- Tampered RGB, wrong-sized, or partially transparent PNGs must produce technical failures.
- Real stdio discovery, tool calls, errors, and persisted assets must work across process restarts.
